# which registry key each audio.cpp family is, decided by hand.
#
# audio.cpp's catalog (data/audiocpp.json) names a family and the packages it
# downloads, and 70 of its families download only from its own shared repo, so
# nothing in the catalog says which checkpoint a family IS. this file does:
# `./scaffold --audiocpp` reads it to draft an entry per family the registry
# does not carry, and to say which existing entry a carried family belongs to.
#
#   <family> <key>      the hub repo of the weights the family converts
#   <family> -          no checkpoint on the hub to key on; the reason follows
#
# `kind=<kind>` after a key overrides the kind read off the family's category
# and tasks, where those say less than the description does.
#
# a key the registry already holds means "add `audiocpp: <family>` there".
